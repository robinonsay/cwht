## Observations (no finding)

- **O-1 (ADR-064 section 2, the pot as a live tuning input).** The A5 reading puts "the fine-tuning potentiometer" inside the tuning logic, and the independent check runs "before PA_EN". The pot is the only tuning path that stays live outside the menu, and so while transmit is armed. An ADC reading that moves within the pot's hysteresis during an over would retune under RF, near an edge across the guard. 07 section 14.2 `SW-SYNTH` row e already rejects "a retune request ... while a transmit sequence is in progress", and REQ-SYS-009 inhibits "whenever" the set frequency is outside the guard. So the provision exists. Request to WP-PDR-33 and WP-PDR-35 to state that the pot is not applied from key-down to the end of the hang, and to WP-PDR-16 for the "during transmission" clause of HZ-008 K7.
- **O-2 (ADR-066 section 2, the sending speed of fault messages).** "The menu letters themselves are sent at the keyer speed." Nothing says what speed the `SW-SAFE` fault annunciation uses. If it reads the menu-set keyer speed, a menu or configuration fault changes the cause message, which ADR-062 says a menu fault cannot do. Request to WP-PDR-33 and WP-PDR-35 to fix the fault message speed inside the fault annunciation unit.
- **O-3 (ADR-067, provenance records).** The 07 section 17.1 rustos rows still read "commit `c54d35a` at this revision" and "every line is the owner's".
