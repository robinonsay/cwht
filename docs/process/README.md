# cwht process documents

`docs/process/` holds the charter and the process documents that expand it. Rule: every document here expands one or more sections of `00-charter.md` and must not contradict it; a conflict is resolved by correcting the process document (a plain commit with a `Refs:` trailer before SRR, `CR-NNN` after), never by silently editing the charter. Each document is reviewed by an independent reviewer agent against the plan items of `docs/templates/peer-review-checklist-requirements.md` section G (CK-REQ-G1 to G8; `08-agent-briefing.md` §3.5) before it is presented at a review; the record is `docs/reviews/<REVIEW>/checklists/plan-<document-stem>.md` with `id: INSP-NNN`. All are baselined at SRR and re-approved at every later review.

## File-name reconciliation

All nine process documents exist under the names the charter §5 lists (verified 2026-09-25): `00-charter.md`, `01-lifecycle-and-reviews.md`, `02-requirements-and-traceability.md`, `03-software-classification-and-rmm.md`, `04-verification-and-validation.md`, `05-configuration-and-data-management.md`, `06-risk-and-decision-analysis.md`, `07-software-engineering-plan.md`, `08-agent-briefing.md`. Earlier drafts referred to `docs/plan/milestones.md` (now `docs/plan/schedule.md`), `docs/research/technology-assessment.md` (now `docs/plan/technology-assessment.md` per the charter) and `docs/templates/checklist-*.md` (now `peer-review-checklist-*.md`); the SEMP and this briefing were corrected on 2026-09-25. Open alignment items between sibling documents are listed in each document's own alignment section (02 §14, 03 §6.5, 05 §14.1, 07 §22, SEMP App. F) and consolidated by Claude in the SRR package's proposed-tailoring section.

## Reading order

New agent: `00-charter.md`, then `08-agent-briefing.md`, then the document for the product type. Reviewer preparing a gate: `01-lifecycle-and-reviews.md`, then `docs/plan/semp.md` §3.4 and §7.4, then the review package.
